# CleanDrive Bot (multi-user, multi-account, v5.0, Google Drive backend)

Чистит метаданные (EXIF/GPS/IPTC/XMP) из фото и файлов без потери качества и
складывает результат на **Google Drive** пользователя. Каждый может
подключить **несколько** своих Google-аккаунтов и переключаться, на какой из
них грузить. По итогу — публичная ссылка на папку (доступ по ссылке, без
входа в аккаунт у получателя) и честный отчёт: что загрузилось, что нет.

## Почему Google, а не Яндекс
Публичная ссылка на **папку** в Яндекс.Диске требует от получателя войти в
свой Яндекс-аккаунт (это подтверждённое ограничение платформы, не
настраивается). У Google Drive такого ограничения нет — "anyone with the
link" работает по-настоящему без авторизации получателя.

## Кто может подключиться
Любой Google-аккаунт — не только тот, под которым создавался OAuth-клиент в
Google Cloud. Приложение опубликовано (**In Production**) с несенситивным
scope `drive.file`, поэтому белого списка test users нет — подключиться
может любой Google-логин, включая любой из твоих собственных.

## Как это работает
1. `/start` → кнопка «Подключить Google Drive» → пользователь логинится **на
   странице Google** и разрешает доступ. Пароль бот не видит никогда.
   Уже подключённым пользователям кнопка предлагает «➕ Подключить ещё
   аккаунт» — можно держать сразу несколько своих Дисков и переключаться
   между ними через `/accounts`.
2. `/settings` → чекбоксы: чистить метаданные (по умолчанию ✅), обезличивать
   имена файлов (по умолчанию ⬜) и **папка по дате съёмки без вопроса** (по
   умолчанию ⬜). Настройки общие для пользователя и не зависят от того,
   какой Google-аккаунт сейчас активен.
   - При включённой «папке по дате» бот не спрашивает имя папки вообще —
     смотрит EXIF-дату съёмки файлов (`DateTimeOriginal`/`CreateDate`),
     берёт дату, которая встречается чаще в пачке (при равенстве — самую
     раннюю), и сразу пишет «Папка будет создана автоматически: DD.MM.YY» и
     грузит. Если у файла нет EXIF-даты вообще (не фото, скан) — использует
     время отправки сообщения в Telegram, а если и его нет — сегодняшнюю
     дату. Один пакет файлов = одна папка, даже если в пачке разные даты.
3. Пользователь шлёт фото/файлы (можно альбомом, или несколько файлов подряд
   — они соберутся в один пакет автоматически).
4. Бот сразу сообщает, что применил (чистка/обезличивание — по текущим
   настройкам), показывает ⚠️ если есть GPS, и спрашивает **только имя
   папки** (с кнопкой отмены).
5. Грузит файлы на **активный** аккаунт по одному (если один не загрузился —
   остальные всё равно продолжают грузиться), присылает точный отчёт по
   именам и ссылку на папку — доступна кому угодно по ссылке, без входа в
   Google-аккаунт.
6. Успешно загруженные исходные сообщения удаляются из чата.

## Настройка

### 1. Google Cloud
- **https://console.cloud.google.com/** → создать/выбрать проект
- Включить **Google Drive API**: поиск "Drive API" → Enable
  (https://console.cloud.google.com/apis/library)
- **Google Auth Platform** (в интерфейсе Google Cloud — раньше называлось
  "OAuth consent screen"):
  - Заполнить Branding: App name, support email, developer contact email
  - User Type: **External**
  - **Audience** → добавить свою почту в Test users (пока не опубликовано),
    либо сразу нажать **Publish App** (перевести в статус **In Production**)
    — для scope `drive.file` это разрешено без верификации Google, так как
    scope несенситивный
- **Credentials → Create Credentials → OAuth client ID**
  (https://console.cloud.google.com/apis/credentials)
  - Application type: **Web application**
  - Authorized redirect URIs → `https://<твой-render-домен>.onrender.com/oauth/callback`
  - Сохрани **Client ID** и **Client secret** (можно скачать `client_secret.json`)

### 2. Supabase
Новая схема (две таблицы вместо одной — настройки отдельно от аккаунтов,
потому что теперь аккаунтов может быть несколько на одного пользователя):
```sql
create table if not exists user_settings (
  telegram_id bigint primary key,
  clean_metadata boolean default true,
  anonymize_names boolean default false,
  auto_date_folder boolean default false
);

create table if not exists google_accounts (
  id bigserial primary key,
  telegram_id bigint not null,
  email text not null,
  access_token text not null,
  refresh_token text not null,
  is_active boolean not null default false,
  created_at timestamptz default now(),
  unique (telegram_id, email)
);
create index if not exists idx_google_accounts_telegram on google_accounts(telegram_id);
```

**Если у тебя уже есть `user_settings` без колонки `auto_date_folder`** —
просто добавь её:
```sql
alter table user_settings
  add column if not exists auto_date_folder boolean default false;
```

**Если обновляешься с предыдущей версии (таблица `disk_users`)** — данные
автоматически не переносятся (разная структура, разные ключи). Проще всего:
выполнить SQL выше (создаст новые таблицы), задеплоить новый код, затем в
боте `/start` и подключить аккаунт(ы) заново — старая `disk_users` останется
неиспользуемым мёртвым грузом, её можно потом дропнуть (`drop table
disk_users;`) когда убедишься, что всё работает.

### 3. Telegram
Токен бота у @BotFather → `BOT_TOKEN`.

Узнать свой numeric Telegram ID (для `ADMIN_ID`): напиши **@userinfobot** в
Telegram, он в ответ на любое сообщение присылает твой ID.

### 4. Render (Web Service, Docker)
Задеплой репозиторий (Dockerfile нужен ради `exiftool`).
Environment variables:
- `BOT_TOKEN`
- `ADMIN_ID` — твой numeric Telegram ID (см. выше). Только этот пользователь
  может использовать бота вообще — все остальные полностью игнорируются на
  уровне диспетчера, ещё до входа в любой хендлер (даже /start не ответит).
- `GOOGLE_CLIENT_ID`
- `GOOGLE_CLIENT_SECRET`
- `OAUTH_REDIRECT_URI` = `https://<твой-домен>.onrender.com/oauth/callback`
  (ровно как в Google Cloud Console)
- `SUPABASE_URL`
- `SUPABASE_KEY`

`PORT` Render прокидывает сам; на нём поднимается OAuth-callback и `/health`.

## Команды
- `/start` — подключить Диск (или ещё один) / инструкция
- `/accounts` — список подключённых Google-аккаунтов, тап переключает активный
- `/settings` — чекбоксы: чистить метаданные, обезличивать имена
- `/logout` — удалить ВСЕ подключённые аккаунты (доступ можно также отозвать
  на myaccount.google.com/permissions)

## Нюансы
- Присылай как **Файл/Document**, иначе Telegram сам пережмёт «Фото».
- Настройки (`/settings`) применяются молча к каждой новой загрузке —
  бот больше не спрашивает "чистить?"/"переименовать?" на каждый пакет
  файлов, только сообщает, что применил, перед вопросом об имени папки.
  Настройки общие для всех подключённых аккаунтов одного пользователя.
- Загрузка всегда идёт на **активный** аккаунт — смотри/переключай в
  `/accounts`. Подключение нового аккаунта через `/start` автоматически
  делает его активным.
- Загрузка идёт по одному файлу; если конкретный файл не загрузился —
  остальные всё равно продолжают, в конце — точный список удачных/неудачных.
- Скачивание файлов, проверка/чистка EXIF и загрузка на Drive выполняются
  параллельно (с ограничением на количество одновременных операций —
  `DOWNLOAD_CONCURRENCY`, `EXIF_CONCURRENCY`, `UPLOAD_CONCURRENCY` в
  `main.py`), а не строго по одному — так быстрее на больших пачках файлов.
  `exiftool`-вызовы вынесены в отдельные потоки (`asyncio.to_thread`), чтобы
  не блокировать весь бот на время их работы.
- Список команд бота (синяя кнопка "Меню" в чате) регистрируется при
  старте через `bot.set_my_commands()`.
- При истечении access-токена мидбатча бот делает ровно одно обновление
  токена и повторяет только тот файл, что не загрузился — Google Drive не
  умеет "перезаписывать" файл по имени как Яндекс (`overwrite=true`), так что
  повтор всего пакета создал бы дубликаты; поэтому логика per-item.
- Удаление исходных сообщений из чата — best effort: если Telegram не даст
  удалить (например, сообщение слишком старое), бот сообщит об этом отдельно.
- Приложение в статусе **In Production** с несенситивным scope `drive.file`
  — по нашим данным это снимает лимит в 100 test-пользователей и должно
  убрать протухание refresh-токена через 7 дней (актуально для
  неверифицированных Testing-приложений). Стоит подтвердить эмпирически
  через неделю использования.
- Scope `drive.file`: бот видит только файлы/папки, которые сам создал —
  не весь Google Drive пользователя.
